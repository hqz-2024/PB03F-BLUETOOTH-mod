## 1. 工程说明

基于 PHY62XX SDK 3.1.5 的 BLE 蓝牙桥接固件，三端透传桥接：

```
┌──────────┐  UART1  ┌─────────────┐  UART0  ┌──────────┐
│ 焊机主控A │←──────→│    PB03F     │←──────→│ 第三方设备C│
└──────────┘ 19200   └──────┬──────┘ 19200   └──────────┘
                            │ BLE GATT (FFE0/FFE1/FFE2)
                            ↓
                       ┌──────────┐
                       │ 手机APP B │
                       └──────────┘
```

核心功能：

- **多机型自动适配**：根据主控上报的设备型号自动切换轮询规则与广播布局
- UART1 与主控 12 字节固定包协议通讯（轮询 + 透传）
- UART0 与第三方设备双向透传（心跳机制维持连接）
- BLE GATT（FFE0/FFE1/FFE2）与 App 双向透传
- 三端任意一端操作，主控状态变化实时同步到另外两端

### 支持机型（设备型号自动识别，无需手动配置）

| 设备类型 | 机型 | 系列 | 轮询规则 |
|:---:|------|------|:---:|
| `0x0002` | BTC500DP PRO | BTC | 8 条查询 |
| `0x0003` | BTC550DP Ultra | BTC | 8 条查询 |
| `0x0004` | BTC500DP 7GEN PRO | BTC | 8 条查询 |
| `0x0005` | BTC500DP 5GEN PRO | BTC | 8 条查询（单功能机，不存在的字段回复 0） |
| `0x0006` | MIG145 Pro | MIG | 12 条查询 |
| `0x0007` | MIG135 Pro | MIG | 12 条查询 |

未知型号默认按 BTC 规则轮询（兼容未来机型）。

## 2. 串口配置

### UART1（主控 A）

- 端口：UART1（TX=P24, RX=P23）
- 波特率：`19200` 8N1
- 用途：轮询查询 + 双向透传

### UART0（第三方设备 C）

- 端口：UART0，重映射到 **TX=P33, RX=P32**
- 波特率：`19200` 8N1
- 用途：与第三方设备双向透传（RS485 半双工场景建议使用可控 DE/RE 模块）

> UART0 原默认引脚 P9/P10 为烧录保留口（ROM BootLoader 编程模式），应用启动后释放并重映射到 P33/P32。

## 3. 协议说明

### 数据包格式（两端通用）

每包固定 12 字节：

| 字段 | 包头 | 设备类型 | 命令码 | 数据区 | 校验码 | 包尾 |
| ---- | ---- | -------- | ------ | ------ | ------ | ---- |
| 长度 | 2B   | 2B       | 2B     | 2B     | 2B     | 2B   |

- 包头：`0xAA 0x55`
- 包尾：`0xBB 0x55`
- 校验码 = 命令码 + 数据区（16 位相加）

### 设备类型字段

- `0x8000`：APP 已连接
- `0x0000`：APP 未连接

**轮询帧**：PB03F 根据 BLE 实际连接状态区分（BLE 在线→0x8000，仅 C 在线→0x0000）。
**操作指令**：按发送方（B 或 C）原样透传，不做修改。

### 查询命令（按系列循环轮询）

**BTC 系列（8 条，0x0002-0x0009）**：

| 命令码 | 说明 | 响应码 |
| ------ | ---- | ------ |
| `0x0002` | 模式（钢板/网格/除锈） | `0x0082` |
| `0x0003` | 2T/4T | `0x0083` |
| `0x0004` | 电流 | `0x0084` |
| `0x0005` | 后气时间 | `0x0085` |
| `0x0006` | 维弧时间 | `0x0086` |
| `0x0007` | 气压单位 | `0x0087` |
| `0x0008` | 报警状态 | `0x0088` |
| `0x0009` | 输入电压 | `0x0089` |

**MIG 系列（12 条，0x0002-0x000D）**：

| 命令码 | 说明 | 响应码 |
| ------ | ---- | ------ |
| `0x0002` | 工作模式（MIG/LIFT TIG/MMA） | `0x0082` |
| `0x0003` | 焊丝直径 | `0x0083` |
| `0x0004` | 智能模式开/关 | `0x0084` |
| `0x0005` | MIG 电流 | `0x0085` |
| `0x0006` | MIG 电压调整（-3.0~3.0） | `0x0086` |
| `0x0007` | 2T/4T | `0x0087` |
| `0x0008` | TIG 电流 | `0x0088` |
| `0x0009` | MMA 电流 | `0x0089` |
| `0x000A` | VRD 开/关 | `0x008A` |
| `0x000B` | MIG 电压显示（13.5~24.2） | `0x008B` |
| `0x000C` | 报警状态 | `0x008C` |
| `0x000D` | 输入电压 | `0x008D` |

轮询间隔 100ms/包，BTC 一轮 800ms，MIG 一轮 1.2s。

> 所有主控响应（含非广播字段的 TIG/MMA 电流、VRD 等）均透传给 B 和 C。

## 4. 第三方设备心跳机制（UART0）

### 4.1 心跳帧格式

第三方设备周期性发送心跳帧，PB03F 据此判定设备在线并维持透传通道：

```
AA 55  00 00  00 F1  F1 00  F1 F1  BB 55
包头   设备类型 命令码  数据区  校验码  包尾
```

| 字段 | 值 | 说明 |
| ---- | ---- | ---- |
| 包头 | `AA 55` | 固定 |
| 设备类型 | `00 00` | `0x0000`，忽略/任意（当前约定 0x0000） |
| 命令码 | `00 F1` | `0xF100` |
| 数据区 | `F1 00` | `0x00F1` |
| 校验码 | `F1 F1` | `0xF100 + 0x00F1 = 0xF1F1` |
| 包尾 | `BB 55` | 固定 |

### 4.2 心跳行为

| 动作 | 说明 |
| ---- | ---- |
| 首次收到心跳 | 判定 C 在线 → 启动轮询/透传（若 B 未连接也启动） |
| 持续收到心跳 | 刷新 5s 在线超时定时器 |
| 5s 无心跳 | 判定 C 断连 → 清空 UART0 TX 队列 → 若 B 也不在线则停止轮询 |
| 心跳帧本身 | **不回复、不透传给主控/APP**，仅在 PB03F 内部消化 |

### 4.3 在线判定总逻辑

```
轮询/透传运行条件：B（BLE 连接）或 C（心跳在线）任一成立
停止条件：两者都离线
```

## 5. 三端数据流与优先级

### 5.1 数据流

| 数据方向 | 路径 |
| -------- | ---- |
| B 指令 → 主控 | BLE Write → `bys_uart_send_app_cmd`（原样透传）→ UART1 → 主控 |
| C 指令 → 主控 | UART0 RX → `proxy_uart_rx_callback`（先清 UART0 TX 队列）→ UART1 → 主控 |
| 主控响应 → B/C | UART1 RX → 校验解析 → Notify B + UART0 TX 队列 → C |
| 主控响应 → 广播 | 每包响应刷新广播数据（型号/状态字段） |

### 5.2 操作模式（指令优先）

收到 B 或 C 的操作指令时：

```
暂停轮询（主控只处理操作指令，不受查询打扰）
  → 300ms 内无新指令 → 恢复轮询
  → 连续指令 → 每次刷新 300ms 窗口
```

- B/C 操作指令进 8 槽 FIFO 队列，逐条下发，不连帧不丢帧
- 操作模式下主控对指令的确认回复正常透传给 B/C

### 5.3 排水模式（断联通知）

BLE 断联且 C 也不在线时：

```
以 0x0000（APP未连接）轮询完整一轮（BTC 8条 / MIG 12条）
  → 通知主控 APP 已下线并更新状态
  → 停止轮询，保持广播待机
```

### 5.4 开机预热

进广播后自动轮询完整一轮（无论有无设备连接）：

```
获取设备型号 → 自动切换轮询规则（BTC/MIG）
填充广播数据（型号 + 状态字段）到 RAM 并刷新广播
完成后若无设备在线 → 停止轮询
```

## 6. BLE 广播

广播数据 31 字节，包含 3 个 AD Structure：

- **AD1**（3B）：Flags `02 01 06`
- **AD2**（5B）：Complete Local Name `"BYS"`
- **AD3**（23B）：Manufacturer Specific Data

### BTC 系列布局（偏移 16-29）

| 偏移 | 长度 | 字段 |
| ---- | ---- | ---- |
| 10-15 | 6B | MAC 地址（大端序） |
| 16-17 | 2B | 设备类型 |
| 18-19 | 2B | 模式（钢板/网格/除锈） |
| 20-21 | 2B | 2T/4T |
| 22-23 | 2B | 电流 |
| 24-25 | 2B | 后气时间 |
| 26-27 | 2B | 维弧时间 |
| 28-29 | 2B | 气压单位 |

### MIG 系列布局（偏移 16-29，字段语义不同）

| 偏移 | 长度 | 字段 |
| ---- | ---- | ---- |
| 10-15 | 6B | MAC 地址（大端序） |
| 16-17 | 2B | 设备类型 |
| 18-19 | 2B | 工作模式（MIG/LIFT TIG/MMA） |
| 20-21 | 2B | 焊丝直径 |
| 22-23 | 2B | MIG 电流 |
| 24-25 | 2B | 2T/4T |
| 26-27 | 2B | 报警状态 |
| 28-29 | 2B | 输入电压 |

### GATT 服务

- Service UUID：`0xFFE0`
- Characteristic UUID：`0xFFE1`（Write + Notify，12 字节，App 通讯通道）
- Characteristic UUID：`0xFFE2`（Write + Notify，12 字节，遥控端通讯通道）
- 任一通道写入 → 转发给主控；主控响应 → Notify 给两个通道

## 10. 烧录与 OTA

### 串口烧录（P9/P10）

- ROM BootLoader 在应用启动前监听 UART0（P9/P10）握手信号
- 上电/复位后立即用 PhyPlusKit 连接即可进入编程模式
- 应用运行期间 UART0 已重映射到 P33/P32，不影响烧录

### OTA 升级

- 触发包：`AA 55 XX XX 00 FE FE 00 FE FE BB 55`（cmd=0xFE00, data=0x00FE）
- 可由 B、C 或主控任意一端发出
- PB03F 收到后向下位机连发 3 包通知（50ms 间隔）→ 软复位进入 OTA 模式
- 使用 PhyPlusKit 通过 BLE 连接 `PPlusOTA` 设备升级
