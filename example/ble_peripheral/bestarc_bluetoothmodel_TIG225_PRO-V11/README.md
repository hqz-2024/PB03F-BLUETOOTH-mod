## 1. 工程说明

基于 PHY62XX SDK 3.1.5 的 BLE 蓝牙桥接固件，适用于 **ACDC TIG225 Pro** 焊机。

核心功能：

- 通过 UART1 与主控（焊机）进行 12 字节固定包协议通讯，轮询查询设备状态
- 通过 BLE 广播上报设备状态（焊接模式、2T/4T/点焊、电流、脉冲、报警、输入电压）
- 通过 BLE GATT（FFE0/FFE1）实现 App 与主控的双向透传

数据流向：

```
[焊机主控] ←UART1 115200→ [PB03F 蓝牙模块] ←BLE→ [手机 APP]
```

- **主控 → APP**：主控回复的每一包数据原样 Notify 给 APP
- **APP → 主控**：APP 写入 FFE1 的每一包数据原样转发给主控
- **主控主动上报**：协议规定主控不主动上报，必须由本模块主动发送查询指令，
  主控收到查询后回复对应数据包

设备型号：根据主控上报数据进行广播，无需手动配置；

ACDC TIG225 Pro 设备号：0x0009（沿用 TIG 系列机型码，实际以主控上报值为准）

## 2. 协议说明

### UART 参数

- 波特率：`115200`，8N0（**注意：TIG225 Pro 由 TIG215 Pro 的 57600 提升为 115200**）
- 端口：UART1（TX=P24, RX=P23）

调试日志串口（UART0，TX=P09/RX=P10）波特率由 SDK 的 `dbg_printf_init()`
决定（`components/driver/log/my_printf.c`，当前为 115200），与下位机协议波特率无关，
本次未随协议改动。

### 数据包格式

每包固定 12 字节：

| 字段 | 包头 | 设备类型 | 命令码 | 数据区 | 校验码 | 包尾 |
|------|------|---------|-------|-------|-------|------|
| 长度 | 2B   | 2B      | 2B    | 2B    | 2B    | 2B   |

- 包头：`0x55AA`（发送字节序 `AA 55`）
- 包尾：`0x55BB`（发送字节序 `BB 55`）
- 校验码 = 命令码 + 数据区（取低 16bit）

### 上位机发送时设备类型字段

- `0x8000`：APP 已连接
- `0x0000`：APP 未连接

设备（主控）上报时低字节为本机机型，TIG 系列文档取值为 `0x0009`
（TIG225 Pro 协议文档未给出新值，实际以主控上报为准，固件原样透传）。

### 电流范围（协议数据码说明）

| 模式 | 220V | 110V |
|------|------|------|
| STICK 焊接电流 | 20~180A | 20~140A |
| TIG(DC) 焊接/起弧/收弧电流 | 10~225A | 10~160A |
| TIG(AC 方波) 焊接/起弧/收弧电流 | 10~225A | 10~160A |
| TIG(AC 三角波) 焊接/起弧/收弧电流 | 10~225A | 10~160A |

电流上限仅由 APP/主控侧做范围限制，蓝牙模块按 12 字节包原样透传。

### 查询命令（21 条循环轮询）

| 命令码 | 说明 | 响应码 | 数据范围 |
|--------|------|--------|---------|
| `0x0002` | 模式 | `0x0082` | 0=STICK 1=TIG(DC) 2=TIG(AC方波) 3=TIG(AC三角波) |
| `0x0003` | 热引弧电流 | `0x0083` | 0~100A，0=OFF |
| `0x0004` | 推力电流 | `0x0084` | 0~100A，0=OFF |
| `0x0005` | VRD | `0x0085` | 0=关 1=开 |
| `0x0006` | 焊接电流 | `0x0086` | 见协议电流范围表 |
| `0x0007` | 2T/4T/点焊 | `0x0087` | 0=2T 1=4T 2=点焊 |
| `0x0008` | 脉冲 | `0x0088` | 0=关 1=开 |
| `0x0009` | 点焊时间 | `0x0089` | 1~100（APP 加小数点：0.01~1.00S） |
| `0x000A` | 前气时间 | `0x008A` | 1~30（APP 加小数点：0.1~3.0S） |
| `0x000B` | 起弧电流 | `0x008B` | 见协议电流范围表 |
| `0x000C` | 缓升时间 | `0x008C` | 0~15S |
| `0x000D` | 脉冲占空比 | `0x008D` | 10%~90% |
| `0x000E` | 脉冲频率 | `0x008E` | 5~2000（<10 加小数点：0.5~200.0HZ） |
| `0x000F` | 脉冲谷值 | `0x008F` | 5%~95% |
| `0x0010` | AC 频率 | `0x0090` | 40~200HZ |
| `0x0011` | AC 占空比（反向电流） | `0x0091` | 20%~60% |
| `0x0012` | 缓降时间 | `0x0092` | 0~25S |
| `0x0013` | 收弧电流 | `0x0093` | 见协议电流范围表 |
| `0x0014` | 后气时间 | `0x0094` | 0~150（APP 加小数点：0.0~15.0S） |
| `0x0015` | 报警 | `0x0095` | 0=无报警 1=过流 |
| `0x0016` | 输入电压 | `0x0096` | 0=110V 1=220V |

轮询间隔 100ms/包（含 15ms 包间隔），21 包一轮 ≈ 2.4 秒。

### 设定命令（APP 下发，本模块透传不解析）

`0x0200` 模式、`0x0300` 热引弧电流、`0x0400` 推力电流、`0x0500` VRD、
`0x0600` 焊接电流、`0x0700` 2T/4T/点焊、`0x0800` 脉冲、`0x0900` 点焊时间、
`0x0A00` 前气时间、`0x0B00` 起弧电流、`0x0C00` 缓升时间、`0x0D00` 脉冲占空比、
`0x0E00` 脉冲频率、`0x0F00` 脉冲谷值、`0x1000` AC 频率、`0x1100` AC 占空比、
`0x1200` 缓降时间、`0x1300` 收弧电流、`0x1400` 后气时间。

设备确认码为设定码 `| 0x8000`（如 `0x0200` → `0x8200`），
错误码 `0x8100`（数据区 `0x0001`＝设备正在工作，暂不接受 APP 调动显示面板及功能）。

### 模式说明

- `0x0000`：STICK
- `0x0001`：TIG(DC)
- `0x0002`：TIG(AC 方波)
- `0x0003`：TIG(AC 三角波)

### OTA 升级（仅对蓝牙模块升级）

触发指令：命令码 `0xFE00`，数据区 `0x00FE`，**设备类型字段忽略**，
可由 APP 或主控任意一方发出。原始报文：

```
AA 55 XX XX 00 FE FE 00 FE FE BB 55
```

流程：模块收到触发包后 → 向主控连发 3 包 OTA 通知（每包间隔 50ms）→
约 150ms 后写 `OTA_MODE_SELECT_REG(0x4000f034)=0x2` 并软复位进入 OTA 模式，
BLE 广播名变为 `PPlusOTA`。

模块下发给主控的 OTA 通知包（共 3 包，内容相同）：

```
AA 55 00 80 00 FE FE 00 FE FE BB 55
```

升级工具：使用 **PhyPlusKit**（奉加微官方工具）通过 BLE 连接 `PPlusOTA` 设备，
选择新固件 hex 升级；升级完成后设备自动重启，BLE 广播名恢复为 `BYS`。

## 3. BLE 广播

广播数据包含 3 个 AD Structure（AD1 3B + AD2 5B + AD3 22B）：

- **AD1**：Flags `02 01 06`
- **AD2**：Complete Local Name `"BYS"`
- **AD3**：Manufacturer Specific `16 FF` + 20 字节状态数据

AD3 状态字段（小端序）：

| 偏移 | 长度 | 字段 |
|------|------|------|
| 10-15 | 6B | MAC 地址（大端序） |
| 16-17 | 2B | 设备类型 `0x0009` |
| 18-19 | 2B | 焊接模式 |
| 20-21 | 2B | 2T/4T/点焊 |
| 22-23 | 2B | 焊接电流 |
| 24-25 | 2B | 脉冲开关 |
| 26-27 | 2B | 报警 |
| 28-29 | 2B | 输入电压 |

### GATT 服务

- Service UUID：`0xFFE0`
- Characteristic UUID：`0xFFE1`（Write + Notify，12 字节）
- App 写入 FFE1 → 转发给主控（设备类型字段自动改写为 `0x8000`）
- 主控响应 → Notify 给 App

## 5. 数据流

### App → 主控

1. App 写入 FFE1（12 字节）
2. `simpleProfileChangeCB()` 读取数据
3. `bys_uart_send_app_cmd()` 修正设备类型字段为 `0x8000` 后入队
4. UART1 发送给主控

### 主控 → App

1. 主控返回 12 字节响应
2. `uart_rx_cb()` 缓存数据，触发 `BYS_UART_RX_EVT`
3. `bys_uart_process_rx()` 校验并解析
4. `apply_response()` 更新 `g_bys_state`
5. `bys_uart_rx_callback()` → `simpleProfile_Notify()` 透传给 App
6. `bys_update_adv_data()` 刷新广播字段
